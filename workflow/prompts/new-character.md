Use the skills in this workspace to process the new case in inputs/.

First inspect the brief, references and existing assets. Write artifacts/case-plan.md
with the actual start checkpoint, part inventory, units/axes/pose, protected state,
requested result, tools available, per-stage acceptance and stopping conditions.
Do not inherit another character's colors, body coordinates, part names, skeleton,
model budget, successful checks or failed candidates.

If only an image exists, use reference -> normalized A-pose when needed -> reviewed
semantic part references -> generation. Preserve an already suitable pose. Decide
parts from the reference and brief; don't always split head/hair or regenerate assets.
Use the configured generation provider, retain task handles and originals. Record
unavailable generation backends honestly; don't substitute unrelated meshes.

If meshes already exist, begin with inventory/inspection and three-d-ai-lab.
If an assembly exists, branch it and edit only the requested defects. Use
observe -> diagnose -> act -> geometry/native-material inspection -> review.
For color-only repairs use character-material-refinement. Keep same-camera four
views and closeups; don't accept zero crossing counts with visibly broken surfaces.
Use the case's own local-repair and material guides when relevant.

Only when requested, continue accepted assembly through optional part upgrade,
character-rigging, pose review, and character-fbx-export. Use the actual supplied
skeleton, preserve the body pose, bind all required parts and verify fresh imports.
Blender-only tasks leave engine checks deferred. Facial animation is not implicit.

Save editable artifacts, comparisons and a concise report with passed checks and
remaining limitations. A selected local Lab revision is not global character quality
acceptance. Batch cases must have separate inputs, sessions, provider task IDs and
outputs. Do not start subagents unless the user requests delegation.
